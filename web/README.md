# 农业病害智能检测系统（Web 展示层）

基于最终锁定模型 **PP-YOLOE+-m**（EXIF-fix 数据，VAL=0.428，独立 TEST=0.417）与已验证的
`inference/` 推理核心，提供适合 **AI+农业比赛答辩** 的 Gradio Web 展示界面。

> 约束声明：本系统不训练、不调参、不修改 checkpoint、不修改数据集、不访问 TEST、
> 不做模型转换与 RK3588 部署；仅做 Web 展示层与系统工程化，不改变模型推理逻辑。

## 1. 启动

```bash
# 在工程根目录（AIC2026_AgriVision/）下执行
python web/app.py
# 浏览器访问 http://127.0.0.1:7860
```

启动时自动执行**自检**：模型文件 / 配置文件 / 类别映射 / 推理后端，并**只加载一次模型**。
默认运行环境：本地 Windows + PaddlePaddle 3.3.0 + CPU（不修改本地 Paddle 版本；
正式训练/TEST 环境仍为 AutoDL Paddle 2.6.2）。

> 兼容性说明：若当前环境（企业代理 / VPN / 沙箱）会拦截对 127.0.0.1 的预启动探测，
> 程序会自动启用"本地兼容模式"继续启动（不修改任何第三方库文件），本地演示不受影响。

## 2. 功能清单

| 功能 | 说明 |
|---|---|
| 图片上传 | 单张 / 多张 / 拖拽（jpg、jpeg、png、bmp、webp） |
| 置信度阈值 | 默认 0.5，可调；明确标注为推理阈值（非训练参数） |
| 开始检测 / 清空 | 一键检测；清空后重新上传 |
| 结果可视化 | 原图比例画框 + 类别 + 置信度 + 标题/模型名/目标数/真实耗时 |
| 原图 vs 检测对比 | 选择图片查看左右对比 |
| 结果表格 | 序号、类别、置信度、x、y、width、height（含图片名） |
| 类别统计图 | 当前批次各病害类别检测数量（来自实际推理结果） |
| 批次汇总 | 总图片数、成功/失败、总目标数、总耗时、平均耗时、实际 FPS |
| 结果下载 | 检测结果图片、JSON、CSV、类别统计、批次汇总 |
| 异常处理 | 模型/配置缺失、图片损坏、空输入、无检测目标、Paddle 不兼容等给出中文提示 |

## 3. 页面结构

`图片上传 → AI 病害识别 → 结果可视化 → 统计分析`

- **系统信息**：当前设备（CPU/实际检测到的 GPU）、Paddle 版本、模型、输入尺寸、类别数。
- **模型评测**：VAL mAP@0.5:0.95=0.428（模型选择依据）、TEST mAP@0.5:0.95=0.417
  （明确标注"独立 TEST 最终评估结果"，不重新计算）。
- **边缘部署**：已预留 RKNNBackend 接口，后续可迁移至 RK3588（未完成部署）。
- **系统介绍**：基于 PP-YOLOE+-m 实现 13 类植物病害检测，支持图片级/批量检测、
  结果可视化与统计分析，预留边缘设备部署接口。

## 4. 目录结构

```
web/
├── app.py                # Gradio 界面与事件
├── backend.py            # DetectorBackend 单例 + 启动自检
├── config.py             # UI 常量 + 固定模型性能记录（复用 inference/config.py）
├── requirements_web.txt
├── README.md
├── outputs/              # Web 检测输出（run_YYYYMMDD_HHMMSS/）
└── tmp/                  # 上传文件暂存
```

## 5. RK3588 迁移接口

Web 层通过 `inference.detector.DetectorBackend`（当前 PaddleBackend）调用推理，
**不直接依赖 Paddle**。后续新增 `RKNNBackend(DetectorBackend)` 并在
`inference.detector.create_backend()` 注册后，本 Web 层**无需改动**即可切换。

## 6. 已知限制

- 本地 CPU 推理约 0.4 FPS（640×640），演示时单图/小批量为宜。
- 项目无官方中文类名映射，默认显示英文；填写 `CLASS_NAMES_CN` 后自动启用双语。
- 上传图片若带 EXIF 旋转，建议先转正再上传（本数据集图片已烘焙处理）。
